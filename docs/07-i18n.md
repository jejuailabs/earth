# 07. 다국어(i18next) 구조

## 1. 라이브러리

- `i18next` + `react-i18next` (Next.js 사용 시 `next-i18next` 또는 App Router용 경량 커스텀 연동 검토)
- 언어 감지: 브라우저 언어 자동 감지 + 유저가 직접 전환 가능한 UI 토글 제공

## 2. 지원 언어 (제안, 확정 필요)

- 한국어(ko) — 기본값
- 영어(en)
- 그 외 언어는 서비스 확장 시 추가 (일본어/중국어 등 후보)

## 3. 번역 리소스 구조

```
/locales
  /ko
    common.json      # 공통 UI 텍스트 (버튼, 메뉴 등)
    game.json        # 게임 내 텍스트 (매치 결과, 알림 등)
    admin.json        # 어드민 패널 텍스트
    shop.json         # 상점 아이템 관련 텍스트
  /en
    common.json
    game.json
    admin.json
    shop.json
```

- 네임스페이스를 화면 단위로 분리해, 필요한 페이지에서만 해당 네임스페이스를 로드 (번들 크기 최적화)

## 4. 콘텐츠 데이터의 다국어 처리 (Firestore)

정적 UI 텍스트가 아닌 **관리자가 입력하는 콘텐츠**(스테이지 이름, 상점 아이템 이름 등)는 번역 파일이 아니라 Firestore 문서 내 다국어 맵 필드로 관리합니다.

```ts
name: {
  ko: "사막의 정복자",
  en: "Desert Conqueror"
}
```

- 어드민 패널의 스테이지/상점 아이템 편집 화면에서 언어별 입력 필드를 제공 (docs/06-admin-panel.md 참고)
- 미입력 언어는 기본 언어(ko) 값으로 폴백

## 5. 사용 예시 (제안 패턴)

```tsx
const { t } = useTranslation("game");
<p>{t("match.result.victory")}</p>
```

```tsx
// Firestore 콘텐츠 다국어 필드 사용 시
const { i18n } = useTranslation();
const stageName = stage.name[i18n.language] ?? stage.name["ko"];
```

## 6. 열린 질문

- 최종 지원 언어 목록 확정
- 번역 문자열 관리 방식 — 초기엔 파일 직접 편집, 이후 규모가 커지면 별도 번역 관리 툴(예: Lokalise) 도입 검토
