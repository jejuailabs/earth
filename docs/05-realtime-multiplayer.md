# 05. 실시간 멀티플레이 & 매칭 구조

## 1. 매치 유형 4종

| 유형 | 방 생성 | 봇 사용 | 조작모드 |
|---|---|---|---|
| 솔로 봇전 | 없음 (즉시 시작) | O (전원 봇) | 자유 선택 |
| 퀵매치 (캐주얼) | 없음, 자동 매칭 | 인원 미달 시 봇으로 채움 | 자유 선택 |
| 랭크 매치 | 없음, 자동 매칭 | 사용 안 함, 전원 모일 때까지 동시 대기 | 통일 또는 별도 리그 (미정) |
| 커스텀(친구) 방 | 방 코드로 생성/초대 | 호스트가 설정 | 호스트가 설정 |

### 퀵매치 상세 로직 (제안)
1. 큐 진입 → 5~10초 대기하며 다른 유저 매칭 시도
2. 대기시간 초과 시 남은 자리를 봇으로 채워 매치 시작 (리셋 없이 정식 매치로 진행)
3. 매치 진행 중 실제 유저가 큐에서 매칭되면, 살아있는 봇 하나를 해당 유저로 실시간 교체 (봇이 점유하던 영토는 유지한 채 컨트롤만 이전 — 또는 신규 참가자는 빈 슬롯에서 새로 시작, 구현 난이도에 따라 정책 확정 필요)

### 랭크 매치 상세 로직
- 봇 없이 실제 인원이 다 모여야 동시 시작 (드롭인 금지, 공정성 우선)
- 매칭 대기 중 이탈 시 페널티 정책 필요 (열린 질문)

## 2. 실시간 서버 아키텍처 (제안)

`docs/01-architecture.md`에서 제안한 대로, Vercel과 분리된 상시 구동 서버에서 매치를 처리합니다.

```
[실시간 게임 서버]
  - 룸(Room) 단위로 매치 상태 관리 (매치 = 1 룸)
  - 서버 틱마다(20~30Hz):
      1. 클라이언트 입력 반영 (방향/정지)
      2. 이동 처리 및 충돌(탈락) 판정
      3. 영역 점유 갱신 (flood-fill)
      4. 가중치 존/파워업 스폰 처리
      5. 상태 브로드캐스트 (변경분만 델타로 전송 권장)
  - 매치 종료 시:
      - 최종 결과를 Firestore `matches/{matchId}`에 기록
      - EXP/포인트/랭크포인트 계산 후 `users/{uid}` 갱신 (Firebase Admin SDK 경유)
```

## 3. 클라이언트-서버 통신 페이로드 (제안 스키마)

**클라이언트 → 서버 (입력)**
```json
{
  "type": "input",
  "direction": { "x": 0.7, "y": -0.3 },
  "stop": false
}
```

**서버 → 클라이언트 (상태 델타)**
```json
{
  "type": "stateDelta",
  "tick": 1234,
  "players": [
    { "uid": "abc", "pos": [x, y], "trail": [...], "areaPercent": 12.4 }
  ],
  "capturedCells": [ { "x": 10, "y": 20, "owner": "abc" } ],
  "revealedImageCells": [ { "x": 10, "y": 20 } ],
  "events": [ { "type": "eliminated", "uid": "xyz" } ]
}
```

- 매치 시작 시에는 풀 스냅샷 전송, 이후 틱마다 델타만 전송 (대역폭 절약)
- 클라이언트는 델타 수신 사이 프레임을 보간(interpolation)해 부드럽게 렌더링

## 4. 매치 종료 후 데이터 흐름

1. 실시간 서버가 매치 결과 산출 (참가자별 최종 점령률, 킬수, 순위)
2. Firebase Admin SDK로 `matches/{matchId}` 문서 생성
3. 각 참가자 `users/{uid}` 문서에 exp/points/rankPoints 반영 (트랜잭션 처리 권장)
4. 클라이언트는 결과 화면에서 Firestore 구독 또는 서버 응답으로 결과 표시

## 5. 봇 통합

- 봇은 실시간 서버 내에서 가상 플레이어로 취급 (동일한 상태 구조, 입력만 AI 로직이 생성)
- 봇 tier/행동 로직은 `docs/04-game-mechanics.md` 6장 참고

## 6. 열린 질문 (착수 전 확정 필요)

- 실시간 서버 호스팅 플랫폼 최종 선정 (Fly.io / Railway / Render 등)
- 퀵매치 중 유저 합류 시 "빈 슬롯 신규 시작" vs "봇 영토 그대로 이어받기" 정책
- 랭크 매치 이탈 페널티 정책
- 대규모 배틀로얄(20~50인) 모드는 1차 개발 범위에서 제외하고 추후 확장 (로드맵상 3차 확장)
